# SKYFORGE — Накопленные знания, правила и грабли

> **Назначение:** перенести весь опыт разработки SKYFORGE 0.1.0 в одну
> самодостаточную инструкцию, чтобы при создании *новой игры* (другим ИИ,
> в другой сессии, без истории диалогов) можно было сразу сделать рабочую
> бета-версию и **не наступить повторно ни на одну из этих грабель**.
>
> Это живой документ: дополняй его при каждом новом открытии.

---

## 0. Коротко о проекте-доноре

- **SKYFORGE — Кузница Небес**, alpha 0.1.0, офлайн-мобильная (Android) 3D-песочница:
  физический парящий остров, выживание, конструктор машин, ночные тени.
- **Стек (не менять без причины):** Three.js 0.160, Vite 5, Capacitor 6,
  `@dimforge/rapier3d-compat` 0.14, чистый HTML/CSS UI, Web Audio API (синтез).
- **Платформа:** Android (Honor Magic 8 Pro / современный WebView), только landscape,
  fullscreen, без сети, без разрешений.
- **Архитектура:** `src/main.js` (bootstrap) → `src/game.js` (оркестратор, один RAF-loop)
  → системы `init()/update()/dispose()`. Вся глобальная отладка через `window.__SKY`.

   автоматические headless-тесты на нём — обязательная практика.

## 2. Железные правила кода (из спеки + выстраданы)

- Один и только один `requestAnimationFrame`-цикл; `cancelAnimationFrame` перед стартом.
- **RAF-цикл обязательно обёрнут в try/catch**: одно исключение не должно убивать
  игру (иначе «вечное зависание»). Ошибку логировать один раз, цикл продолжать.
- Никаких `dynamic import()` в игровом бандле. Один Vite-bundle, code splitting off.
- Никаких CDN/внешних запросов в рантайме. Ассеты — либо процедурные, либо
  **вшитые в bundle** (base64). Офлайн-preview (один HTML) обязан работать без сети.
- Никаких аллокаций в hot loop без причины: переиспользуемые scratch-объекты
  (`src/scratch.js`: V3A–V3E, QUATA/B, COLORA–F).
- `object.userData` — контракт: не перетирать целиком, писать поля точечно.
  Все world-объекты имеют `userData.kind`.
- Магические числа — только в `src/config.js`. Части/рецепты/фауна — data-driven.
- Random — seeded (mulberry32 + пермутация), мир `SKY-001` детерминирован.
- Каждый transient-объект (частицы, джойнты, звуки) имеет TTL/pool/гарантированный dispose.

## 3. ГРАБЛИ №1 — зависание игры через 5–10 секунд (самое важное)

Симптом на устройстве: игра запускается, реагирует, через ~5–7 с замирает навсегда.

**Настоящая причина (доказана headless-воспроизведением, а не гаданием):**

> **Любое необработанное исключение в `update()`/`render()` убивает
> requestAnimationFrame-цепочку → игра «зависает».** Коммит-сообщения «починили
> производительность» без поиска исключения — самообман.

Конкретные найденные броски (каждый приводил к freeze):

1. **Rapier WASM-panic на удалённом теле.** Животные держали список фруктов,
   отфильтрованный раз за тик; одно животное съедало фрукт (`removeRigidBody`),
   следующее вызывало `body.translation()` на удалённом теле → Rust panic
   `RuntimeError: unreachable` → необработанное исключение.
   **Решение:** после `removeRigidBody` **обнулять ссылки** (`ent.body = null;
   ent.collider = null`) — тогда устаревшая ссылка падает как обычный JS null,
   а не WASM-panic; и пере-проверять списки `byId.has(id)` перед обращением.
2. **Вызов несуществующего API.** `p.body.setCcdEnabled(true)` — в rapier3d-compat
   0.14 этого метода у RigidBody **нет** (CCD включается на `RigidBodyDesc`).
   **Правило: перед использованием любого Rapier-метода проверять его существование
   в этой версии** (`typeof body.setCcdEnabled`).
3. **Исключение в цикле частиц/звуков/лучей** — любое. RAF-try/catch решает.

**Профилактика (обязательный регламент перед каждой сборкой):**
- Headless-soak ≥ 60–130 симулированных секунд в режимах idle/night/drive/chaos:
  проверять 0 исключений, 0 NaN-тел, отсутствие монотонного роста счётчиков
  (bodies, joints, sceneChildren, particles, timers, audioNodes).
- Включать в диагностику (раз в секунду, ОДНУ строку): `t fps frame state bodies
  colliders joints threeObjects drawCalls triangles particles timers audioNodes`.
- Watchdog: при аномально длинном кадре сохранять предыдущий diagnostic-snapshot.

## 4. ГРАБЛИ №2 — Rapier 0.14 (подводные камни API)

Проверено экспериментами. Это НЕ «как обычно в документации».

1. **`world.castRay` молчит, пока мир не сделал хотя бы один `step()`.**
   Broadphase не инициализирован → все лучи «промахиваются». Решение: `warm()`
   — один `world.step()` сразу после постройки мира (до title-экрана).
2. **Heightfield: индексация `heights[zIndex + xIndex * (ncols+1)]`** (z — быстрая ось).
   Если хранить x-fast (`heights[x + z*(res+1)]`) — коллайдер транспонируется
   относительно визуала (в нашем случае расхождение до 3.5 м): предметы «плавают»,
   камера упирается в неверную поверхность, машины проваливаются.
   **Решение:** транспонировать копию массива при создании коллайдера.
   После фикса расхождение collider vs visual ≤ 0.05 м.
3. **Цилиндрический коллайдер создаётся осью вдоль Y.** Для колеса (ось X) или
   лежащего бревна (ось Z) нужен явный поворот: `ColliderDesc.cylinder(...)
   .setRotation({x:0,y:0,z:√½,w:√½})` для X; для Z — поворот X на 90°.
   Иначе машина раскачивается на «доньях», бревно не катится.
4. **`configureMotorVelocity`/`configureMotorPosition` существуют только у
   multibody-джойнтов.** У `createImpulseJoint` (ImpulseJoint) моторов НЕТ —
   вызов тихо ничего не делает (метода нет). Привод колёс делать вручную:
   torque + скорость-контроллер + traction control (срез тяги при крене),
   или использовать `DynamicRayCastVehicleController` (но он плохо работает
   с жёсткими машинами из многих джойнтов — проверено, вернулись к ручному приводу).
5. **Fixed-джойнт принуждает ОРИЕНТАЦИИ тел быть равными.** Соединение детали
   с yaw=90° и детали с yaw=0° через `JointData.fixed(a1, id, a2, id)` даёт
   взрывной момент при старте. **Решение:** фиксировать текущую относительную
   ориентацию: `frameQ = qB⁻¹·qA` во втором слоте джойнта. И/или в blueprints
   все части класть с identity-rotation.
6. **Raycast-фильтр по группам:** у `castRay` есть параметр группы; не забывать
   исключать тело игрока/машины, иначе луч попадает в себя.
7. **`removeRigidBody` + сохранённые ссылки = WASM-panic** (см. п.3.1).
   После удаления обнулять ссылки ВЕЗДЕ, где тело хранится.

## 5. ГРАБЛИ №3 — Камера (third-person spring arm)

Проблема: камера проходила под/сквозь terrain при некоторых углах → видна пустота.

**Рабочая схема (проверена свипом 1728 комбинаций yaw/pitch, 0 м проникновения):**
1. Target = позиция игрока (+~1.25 м по Y — точка «глаз»).
2. Desired = target + (back-вектор из yaw/pitch) × distance + height + shoulder.
3. **Два Rapier-луча:** target→desired (находит препятствие) и desired→target
   (обратный, ловит геометрию, в которой луч уже «начался»/протёрся).
4. Если хит по `_blocksCamera` (terrain/workshop/rock/ore/tree/crate/log/chunk) —
   дистанция = `toi - 0.3`.
5. **Жёсткий clamp:** `camera.y >= heightAt(camera.x, camera.z) + 0.7`
   (иначе всё равно может просесть между коллайдерами).
6. Плавное восстановление дистанции: in/out smoothing по-разному (быстро внутрь,
   медленно наружу), никаких телепортов.
7. Workshop floor зарегистрировать в physics.sync (kind 'workshop'), чтобы камера
   его видела (иначе «проваливается» сквозь пол мастерской).
8. Окклюзия крупных объектов (деревья между камерой и игроком): Ray от камеры
   к игроку, при попадании в tree/plant — временно opacity 0.22, плавный возврат.

**Композиция:** distance 5.8–6.3, height 2.15–2.25, look target + 1.35,
pitch ∈ [−0.72, 0.92], FOV 52. Персонаж не должен занимать центр кадра.

## 6. ГРАБЛИ №4 — Управление и взаимодействие

**Инверсия движения (жалоба пользователя «стик вправо — идёт влево»):**
- Право от камеры = `cross(forward, up)` = `(-fwd.z, 0, fwd.x)`.
- Старая формула `(fwd.z, 0, -fwd.x)` — это **ЛЕВО** для камеры, смотрящей вдоль −Z.
- Проверять численно: headless-тест «стик вправо → displacement·camRight > 0».
- Орбита камеры: drag вправо → yaw += dx (естественно), иначе «всё зеркально».

**Прицел взаимодействия («удар/срубить не работает»):**
- Луч НЕ от камеры (он указывает НАЗАД, за игрока) — а по направлению взгляда
  персонажа: `dir = (sin(yaw), -0.14, cos(yaw))` от точки `pos + (0,1.2,0)`.
- Плюс низкий луч для предметов у ног (фрукты, куски) и fallback «ближайший
  граблям в 2 м».
- «Собрать» с кустов: у растений часто НЕТ физических коллайдеров — делать
  proximity-проверку (`dist < 2.2`), не raycast.
- Сдача ресурсов в мастерскую — отдельный режим `deposit` при `carry` рядом с workshop.

**Кнопки закрытия окон:** инвентарь/верстак/конструктор обязаны иметь видимую
кнопку × (иначе пользователь застревает, «приходится через паузу»).

## 7. ГРАБЛИ №5 — Конструктор и машины

- **Порты деталей:** каждый joint использует РАЗНЫЕ порты (никаких дублей), иначе
  joint молча не создаётся (`usedPorts`) → машина «недособрана», асимметрична.
- **Якоря портов должны совпадать с геометрией blueprints** в мировых координатах.
  В blueprint: `part_position + port_anchor` обязан быть ОДНОЙ точкой для пары.
  Иначе при Launch машину «разрывает».
- **Все части blueprint'а — identity rotation** (yaw=0), иначе fixed-джойнт
  разворачивает тела с силой (см. п.4.5).
- Launch: `setBodyType(Dynamic)` + `wakeUp()` + angular damping 0.8, linear 0.12.
- Привод колёс: ручной контроллер скорости (torque = clamp(err*2, ±limit)) +
  срез тяги при подъёме носа (`driveScale = clamp((up.y-0.82)/0.18, 0, 1)`) —
  иначе телега «встаёт на дыбы» и улетает.
- Руль: у impulse-джойнтов нет мотора — yaw-assist торком на сиденье
  (`seat.body.addTorque({y: steer*15})`).
- Падение машины с острова: seat.y < −22 → `machineLost()` → stop + респаун
  игрока на остров (не бесконечное падение).

## 8. ГРАБЛИ №6 — Мир/террейн

- Остров = heightmap-плато, но **за обрывом высоты должны конически уходить вниз**
  (не плоская пустота −18): `h = -7 - (r - rimR) * 1.15`. Иначе «пустота под
  зелёной плоскостью» при взгляде сбоку.
- Визуальный объём острова: оболочка `_volumeShell` (rings) начинается у самой
  кромки terrain, цвета soil→rock→deep, днище сходится в точку (~−16).
  Плюс скальные пики снизу. `material.side = DoubleSide` НЕ является решением.
- Респаун при падении: **искать самую высокую точку terrain рядом**
  (`findSafeSpawn`: кольца r=0,2.2,4.4... max height), а не `lastSafe` —
  иначе игрок возрождается на склоне/боковине, откуда не вылезти.

## 9. ГРАБЛИ №7 — Небо, свет, пост (мобильный WebView)

- **EffectComposer (UnrealBloom/OutputPass) на Android выключить полностью** —
  иначе freeze/пересоздание RT. На десктопе можно, на Capacitor — `skipComposer`.
- **Качество (shadow map size и т.п.) замораживать после boot** — менять
  `shadow.mapSize` в рантайме = пересоздание shadow-RT = freeze на Honor.
- **Звёзды:** per-pixel `step(hash(...))` = «шум на телевизоре» (мерцание).
  Правильно: детерминированное поле — одна звезда на ячейку сетки в space
  направления, фиксированная яркость + мягкий twinkle.
- **«Белое пятно спереди»:** солнечный glow `pow(dot,8)*0.28` + светлая haze +
  выбеленный fog + крупный персонаж в центре кадра. Уменьшить glow до ~0.1,
  haze до ~0.06, fog темнее (0x9fb2b8), экспозиция 1.2, камера дальше/выше.
- Облака: выше (44+), прозрачнее (0.24/0.16), opacity при проходе между камерой
  и игроком → 0.08.
- Fog near/far обновлять мягко (30/168), не резко.

## 10. ГРАБЛИ №8 — Android/Capacitor/CI

- `AndroidManifest.xml`: `<uses-permission android:name="android.permission.INTERNET"
  tools:node="remove"/>` — реально убирает INTERNET из APK. Никаких других permission.
- Activity: `screenOrientation="sensorLandscape"`, `keepScreenOn="true"`,
  `configChanges="orientation|keyboardHidden|keyboard|screenSize|locale|smallestScreenSize|screenLayout|uiMode"`.
- Fullscreen immersive + Back → `CustomEvent('sky-back')` → `input.backPressed` → pause.
- `MainActivity`: `FLAG_KEEP_SCREEN_ON`, `WindowCompat.setDecorFitsSystemWindows(false)`,
  hide systemBars, BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE.
- **Подпись:** committed `tools/debug.keystore` (password `debugstore`, alias
  `androiddebugkey`), в CI — secret `DEBUG_KEYSTORE_BASE64` если задан, иначе committed.
  Проверка: fingerprint сертификата (`keytool -printcert -jarfile`), не raw hash.
  Шаг fingerprint валит билд при несовпадении (когда нет secret).
- **versionCode = github.run_number** в CI (иначе 1), versionName = version.txt.
- CI: checkout → Node 20 → Java 17 → Android SDK → `npm ci` → валидация версии →
  `npm run build` → `npx cap sync android` → `./gradlew assembleRelease` →
  fingerprint → rename `skyforge-<ver>.apk` → upload artifact →
  (при `workflow_dispatch publish_release=true`) GitHub Release.
- **Локально APK не собрать** (нет SDK/Java в песочнице) — не обещать «соберу APK»,
  а давать ссылку на Actions artifact. Артефакты GitHub недоступны из песочницы
  (blob заблокирован) — пользователь скачивает сам.
- `workflow_dispatch` может быть запрещён токену бота (403) — пуш-сборки работают всегда.

## 11. Ассеты: проверенные источники (CC0) и как их подключать

| Пак | Лицензия | Формат | Что внутри | Как получить |
|---|---|---|---|---|
| **Kenney Nature Kit** (2.1) | CC0 | GLB (готово), FBX/OBJ | 329 моделей: деревья, камни, пни, брёвна, цветы, грибы, костёр | `kenney.nl/assets/nature-kit` или GLB-редистрибуция на itch.io (eclair-assets) |
| **Quaternius Ultimate Stylized Nature** | CC0 (оригинал); репо-зеркала MIT | FBX (+Godot) | 6 видов деревьев ×5, кусты с цветами, трава, камни — стиль «painterly», теплее Kenney | quaternius.com; GitHub-зеркала `walterpalladino/godot-quaternius-ultimate-stylized-nature` |
| **KayKit** (kaylousberg) | CC0 | glTF + FBX + OBJ | Стилизованный «chunky medieval» (город, природа) — **мультяшный, для «взрослого» тона не подходит** | GitHub `KayKit-Game-Assets/*` |
| **Shapespark plants** | CC0 | glTF/FBX, но файлы в **Git LFS** | Растения, цветы (без деревьев/камней) | GitHub `shapespark/shapespark-assets` |

**Проверенные грабли с ассетами:**
- **Git LFS-файлы из песочницы не скачать** (объекты.githubusercontent.com заблокирован) —
  либо пользователь качает через веб-браузер, либо брать репо без LFS.
- **Проверять LICENSE в репо** (readme недостаточно): ищем `LICENSE*` файл.
  CC0 = «free to use in personal, educational and commercial projects».
  Отклонять NO-LICENSE / CC-BY (нужна атрибуция) / сомнительные.
- **Пак должен быть стилистически единым**, не «коллекция случайных моделей».
- **Тяжёлые пакеты** (Quaternius текстуры 4K, 237 МБ) требуют даунскейла в CI
  (sharp/ImageMagick) — учитывать заранее.

**Как подключать GLB в офлайн-игру (проверенный пайплайн):**
1. Отобрать ~20–40 нужных моделей (3–18 КБ каждая — копейки для бандла).
2. Скрипт `tools/embed_glb.mjs`: читает zip (свой мини-ридер: central directory +
   zlib inflate, без зависимостей), кладёт base64 в `src/gfx/models.js`.
3. `src/gfx/model_lib.js`: при boot `GLTFLoader.parse(dataURI)` (статический импорт,
   без CDN), складывает шаблоны; `get(name)` возвращает клон со baked-scale.
4. В спавнерах: `if (models.ready && models.has(name)) use GLB else procedural fallback`.
5. Преимущество: **один файл preview продолжает работать** (модели внутри JS).
6. Проверить origin: модели должны стоять «ногами» на 0 по Y (у Kenney так;
   если нет — сдвигать при импорте), иначе всё «плавает».

**Важный урок визуала (из фидбека):** замена пропсов на GLB без работы со светом/
материалами/пост-эффектами даёт лишь умеренное улучшение («ну так себе»).
Максимальный скачок даёт связка: качественный пак + lighting/material pass +
атмосфера (fog, цветовая палитра) + композиция кадра.

## 11б. Конвертация FBX→GLB (проверено, важно)

- three.js `FBXLoader` (r160) парсит только FBX ≤ 7.4 и не все; Quaternius
  Stylized Nature — бинарный FBX 7.5+ → «Unknown format». Не тратить время
  на FBXLoader для свежих паков.
- fbx2gltf (facebookincubator) — готовый CLI, но релиз-бинарники лежат на
  `release-assets.githubusercontent.com`, который в песочнице заблокирован;
  на CI-раннере GitHub — доступен (ставится в Actions из Releases).
- Рабочие пути конвертации без участия пользователя:
  1) **CI**: `wget FBX2glTF-linux-x64` из GitHub Releases → `FBX2glTF in.fbx -o out.glb`
     (текстуры кладутся рядом; даунскейл — ImageMagick/sharp).
  2) **CI**: `blender --background --python convert.py` (apt install blender).
  3) Пользователь конвертирует в Blender и загружает GLB.
- ВАЖНО: если пак texture-based (как Quaternius Stylized Nature, 237 МБ PNG),
  без текстур модели выглядят плоско — планировать даунскейл и размер бандла
  заранее.

## 12. Проверенные тест-харнессы (переиспользовать в новой игре)

В `tools/shot/`:
- **`headless-soak.mjs [сек] [idle|night|drive|chaos]`** — гоняет РЕАЛЬНЫЕ системы
  (Rapier + Three в Node, рендер заглушен) через `Game.update()`-эквивалент.
  Проверяет: 0 исключений, 0 NaN, рост счётчиков. Норма: ≥60–130 с, все 4 режима.
- **`move_test.mjs`** — численная проверка «стик вправо = движение вправо» (инверсия).
- **`interact_test.mjs`** — режим «Срубить» перед деревом, сбор волокна,
  респаун «на вершине».
- **`trace-drive.mjs [throttle] [steer] [sec]`** — телеметрия тележки
  (y/pitch/wheelSpin), поиск «взлёта» и тряски.
- `soak.mjs` — браузерный вариант (требует Chromium, в песочнице недоступен).

**Регламент перед каждым push:** `npm run build` → 4 соака × 130 с →
`python3 tools/build_preview.py` → (если менялась физика) trace-drive.

## 13. Что в SKYFORGE 0.1.0 работает / частично / не работает

**Работает (WORKING):** ходьба/прыжок/coyote/jump-buffer; touch-стик + орбита;
grab/throw; рубка дерева → падение → брёвна → пень; добыча камня/руды → куски;
буйность брёвен в пруду; day/night 8 мин; ветер (трава/шарф/флюгер/баллоны);
флора 4+ видов + рост; фауна 3 архетипа (ходят по земле, убегают от машины);
тени ночью + страх света + костёр; выживание (health/hunger/thirst, fruit/вода);
конструктор: ghost/snap/11 типов частей/джойнты; чертёж тележки тем же пайплайном;
launch/seat/drive/exit; крафт ≥15 рецептов (топор/молот/факел/костёр/детали);
save/load localStorage + autosave; синтетический звук; shot-хуки; DBG;
Kenney Nature Kit GLB (32 модели); CI/APK; офлайн-preview.

**Частично (PARTIAL):** погода (drizzle = частицы, без wet-shading); планер
(аэродинамика крыла есть, носимого планера нет); инвентарь (без drag-and-drop);
SSAO (выключен, флаг есть); дальние острова (визуальные); подвеска тележки
(вместо неё traction-control ассист); адаптивное качество (заморожено после boot).

**Не работает / не сделано (NOT IMPLEMENTED):** воксельная раскопка; летающий
корабль; полный визит на дальние острова; SMAA; уникальный визуал всех рецептов.

**Известные проблемы:** редкий drift у кромки (fall-respawn лечит); на слабых
устройствах нужен MEDIUM; бандл большой (Rapier WASM + модели, ~3.1 МБ preview);
визуал «так себе» — свет/материалы/пост — главный кандидат следующего захода.

## 14. Чек-лист «новая игра с нуля → рабочая бета за один заход»

1. **Фундамент:** git-ветка, `npm ci`, Three+Rapier+Capacitor+Vite, version.txt,
   один RAF-loop с try/catch, `window.__SKY`, DBG-строка раз в секунду.
2. **Headless-харнесс с первой минуты** (соак + move/interact тесты).
3. **Мир:** heightfield (помнить про транспонирование!), warm(), конические
   склоны, визуальный объём, респаун на вершине.
4. **Физика игрока:** kinematic capsule + character controller (step/slope/
   coyote/jump-buffer), падение с острова → respawn.
5. **Камера:** spring arm + 2 луча + clamp y≥terrain+0.7 + workshop в sync.
6. **Взаимодействие:** луч по взгляду персонажа + низкий луч + proximity.
7. **Ассеты:** пользователь грузит zip → `embed_glb.mjs` → ModelLib → спавнеры
   с фолбэком. Проверить лицензию (LICENSE-файл в паке).
8. **Машины:** порты уникальны, якоря совпадают, identity-rotation,
   ручной привод колёс + traction control, machineLost.
9. **Мобильная сборка:** composer off на Android, quality frozen, permission off,
   Back→pause, keystore+CI.
10. **Регламент:** build → соаки → preview → push. Никогда не пушить
    «полукомпилируемый» проект.
